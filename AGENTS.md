# Build continuity

Read PROJECT_CONSTITUTION.md and docs/FEATURE_COMPLETION_REGISTER.md before feature work.

The user requires a maintained list of disabled functions and work needed to finalize the system. For each build, update the register when a feature is added, disabled, enabled, released, blocked, verified or deferred. Preserve stable item IDs. Record the next action, dependency, completion stage and evidence. Distinguish code defaults, observed production configuration and a completed live walkthrough; never infer production activation from an environment-variable name or an old sprint note.

Do not mark an item complete from mocks or CI alone when it requires live integration evidence. Record prepared/open PRs separately from deployed features. Keep intentional privacy/authorization protections separate from incomplete work. No secrets, recipient lists, real learner information or private production records belong in the register. When changing companion PEOS/PSG services, update their linked release status here as well.
