
# Founder and support operations
Users open Report an issue / Share feedback. Submission acknowledgements and updates are in-app only. No agent, principal engineer or external delivery provider has been connected in this milestone.

The founder opens /support then Founder control centre, or /founder directly. Access is enforced by the fresh PEOS support context and global founder role. Browse the alphabetical directory and school profiles. Setup tab shows current canonical classes and missing product workspace links; a diagnostic signal is not a repair action. Counts and timestamps are shown without pretending to measure full service health. Billing, location, contacts, historical learner access and attachments are not configured.

Use the support inbox to set status and priority and give a reporter-visible update. Preparing a recommendation stores its proposed change, benefit, risks, submitted validation evidence and rollback plan. To approve, attach the actual prepared pull-request reference and review the evidence independently. Approval starts no deployment, verification or automatic ticket closure. A newer recommendation supersedes an older candidate while retaining its content and decision history in storage. Only the latest candidate can be decided.

Migration 0008 adds the support schema, private tickets, events and proposals. Apply with the checksum-controlled migration ledger after branch verification. Runtime cannot delete records, edit events, change proposal content or create schema objects. Application rollback retains support records. Do not copy ticket narratives, learner information or credentials into the public source repositories.
