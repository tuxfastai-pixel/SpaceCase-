# ADR 0022 — Durable task links and bounded founder review decisions

The PSG engineering store owns append-only task/PR associations, review events and founder decisions. It remains separate from school databases and PEOS identity. Migration 0003 creates three tables with SELECT/INSERT grants to the existing restricted engineering role. No credentials, ownership, schema CREATE, database CREATE, UPDATE or DELETE grants are added. Lifecycle history combines existing events with review events. The task row lock and revision increment serialize link, cancellation, retention and decision mutations.

A founder explicitly associates a PR and exact reviewed head. The signed purpose binds task, opaque source reference, expected task revision, current source revision/open state and target. SpaceCase resolves source metadata from its database after fresh PEOS founder authorization. Client-supplied authority/evidence flags are rejected. PSG reads only task metadata before inspecting public GitHub, holds no database locks during network reads, then locks/rechecks the task before adding the link and audit event atomically. The PR must still have the entered head, be open against main, and match the immutable task base commit. Draft links may be saved but remain workflow blockers. Linking requires an unchanged open source, blocked task and unexpired brief. Identical transition retries return the existing acknowledgement; saving an unchanged current link is rejected without a second event. Updated heads require an explicit new association.

An on-demand summary uses the saved link automatically and reports current metadata, workflow observations and missing evidence. It never reads saved briefs, original ticket narratives, actor identifiers or learner/school data. Missing code-review provenance, reproduction and rollback remain UNVERIFIED; workflow success cannot substitute for them. Repository errors are explicit blockers so a founder can defer work while upstream evidence is unavailable. A short final task lock checks that task metadata and the bounded latest-five decision projection belong to one consistent database state. Observations are snapshots, not an atomic lock across GitHub and both product databases.

The review digest includes task/link metadata, actual source revision/open state, repository facts, blockers and recorded decisions. Observation times are excluded so an unchanged inspection remains stable. A new head, task/link revision, source revision, lifecycle state, expiry or workflow result invalidates the snapshot. SpaceCase/PSG attestations are thirty-second authorization snapshots, as with existing save controls; they do not grant execution authority.

Founders may append CHANGES_REQUESTED, DEFERRED or DECLINED. Each request has an actor-scoped UUID and canonical payload hash; the task update, decision and audit event commit atomically. Exact retries return one decision even after the task advances; reusing the reference for a different payload fails. New decisions re-evaluate the current summary and reject stale digests or changed task metadata. Recording a decision is distinct from cancelling a task. PostgreSQL intentionally excludes APPROVED from the decision constraint; API layers reject it before storage. No unverified JSON flag or manually selected checkbox can bypass missing provenance. A future verified-evidence stage must deliberately extend both policy and storage before approval can be enabled. All results grant no execution or release permission.

Rollout: verify migration and grants on the isolated verification database and real PostgreSQL CI, apply the additive migration to the dedicated production engineering database, deploy the backward-compatible PSG control service, then expose the new product UI. Existing lifecycle grants and brief retention remain intact. Rollback can restore prior app/service code without dropping review tables or history.
