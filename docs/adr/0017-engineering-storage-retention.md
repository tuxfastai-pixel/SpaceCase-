# ADR 0017 — Founder save flow and seven-day brief retention

Decision: expose explicit save consent and stable same-payload retries in the founder engineering desk. Only product-confirmed configuration enables saving. Requests freeze the reviewed draft and commit while an outcome is uncertain; retries reuse the same request UUID and content. A successful response must match source/revision/digest/commit and explicitly report no execution. Preparing/copying alone remains ephemeral. No brief is placed in browser storage.

Reviewed brief content expires seven days after task creation. Task references, exact commits, digests and audit events remain as minimal idempotency tombstones. A time-derived briefAvailable field becomes false at expiry even before physical cleanup. The daily PSG cron clears due brief JSON in bounded batches, increments task revisions and appends BRIEF_EXPIRED events atomically. It is a narrowly scoped SECURITY DEFINER function with fixed pg_catalog search path, fully qualified tables, no dynamic SQL and bounded batch input. The runtime cannot directly modify content or extend expiry. Concurrent cleanup/cancellation uses row locks; repeated cleanup is harmless. Physical cleanup may lag until the scheduled job, and backups retain their independent provider recovery history.

Cron access requires an independent production-only CRON_SECRET and enabled ledger. No scheduled model calls or code runner are added. Purging content never revives or recreates cancelled/expired work. Monitoring must investigate repeated cleanup failures or more than 2,000 due briefs per daily run; execution must never consume expired content. This policy covers reviewed brief content, not an indefinite promise to erase every operational audit record or provider backup.

Storage rollout: verify migrations on a separate empty database on a non-production Neon branch, then initialize a dedicated production engineering database with restricted runtime access. Scope signing key, public key, database credential and cron secret to their respective production projects. Preview deployments stay disabled. Activate saving only after both product and service releases are ready, with synthetic live smoke checks. No school data migration, paid model, external recipient or production code execution is authorized by saving.
