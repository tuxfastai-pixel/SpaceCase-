# Reviewed vision reading and separate PSG execution

The teacher first confirms page identity/order, requests a vision reading without a memorandum, corrects/checks the extracted text, and then requests draft marks with the fixed rubric and original photos. Manual marking stays independent of this path. Transcription is fallible work evidence, not a canonical learner record.

New product records are photo-quality measurements, raw assistant reading, separately saved teacher-reviewed transcription, READ/MARK execution purpose and a one-use claim timestamp. Photo changes clear reading, reviewed transcription, proposals and draft scores. Source revisions reject stale transcription edits and late responses. Pages still marked uncertain cannot support a confident numeric AI mark; both the service and app reject such output. Final scores still come only from an explicitly saved per-question teacher review and approval.

Basic image checks use pixel dimensions and global contrast. Their warnings do not establish handwriting readability, blur, glare, crop completeness or OCR accuracy. Original normalized uploads are preserved. Older uploads have unknown quality metadata; none is fabricated. An AI request permits at most 2 MB of total image bytes and a 4 MB serialized request to fit a bounded server request. Oversized sets require smaller/fewer clear photos or manual marking, rather than silently reducing the evidence further.

The PSG service is a separate deployable workspace at `services/psg-ai`. Source is co-located for the versioned shared contract, but it owns no SpaceCase domain data and receives no database, Blob, PEOS or Supabase credential. All product authorization, records and approved results remain behind SpaceCase APIs. The service calls the provider through Vercel AI Gateway using its own OIDC/API-key scope, with no direct provider credentials, tools or autonomous approvals.

Before spending, the service authenticates the caller, validates bounded JPEG-only inputs, confirms current model metadata for image/structured-output capability and all-endpoint no-training/ZDR eligibility, and asks SpaceCase for a durable one-use permit. The claim is bound to actor, school, assessment, submission, source revision, mode and input hash. The service cannot invent jobs, read product records or obtain image URLs through that endpoint. It receives only an allowed/denied response. A successful claim is never automatically refunded/replayed after timeout: an explicit new teacher request is needed. No retry loop can duplicate model spend for the same job.

SpaceCase checks current teacher and learner authority before disclosure and after response. A claim additionally checks job freshness, unchanged submission and active local workspaces. A global serialized rolling-24-hour claim cap covers both READ and MARK; failed claimed attempts count conservatively. The default cap is zero, execution is disabled by default and a model must be explicitly selected. This is a call-count limit, not a dollar-budget guarantee.

Provider calls require `zeroDataRetention: true` and `disallowPromptTraining: true` in Gateway options and do not configure BYOK or fallback models. Activation needs an eligible provider/plan and approved model/retention/budget policy; no paid plan, AI key or model request is created as part of code verification. Gateway metadata/policy checks alone are not evidence of real handwriting accuracy. A separate synthetic pilot is required before learner-work activation.

No page bytes, transcript, memorandum or feedback are written to service logs, claim/audit metadata or a shared service database. SpaceCase retains raw/teacher-reviewed reading under the existing learner-work retention boundary. The service returns a model execution ID, selected model and policy version, which the product records with the request/input hash. Prompts are versioned in source. There is no transfer to Atlas.
