# ADR 0025 — Live GitHub evidence and proof-bound founder approval

Goal: replace unverified assertions with source-bound observations and explicit independent attestations before a founder may approve. This grants a recorded decision, never agent execution, repository writes, merge permission or deployment.

The existing public fixed-repository inspector establishes current PR/head/base and Validate workflow attempts. The verifier additionally reads GitHub's current PR author, complete bounded reviews, inline comments, the pinned attempts' jobs, current run states, and immutable proof-file bytes. It never sends packet narratives to GitHub or follows arbitrary content/download URLs. Public GETs carry no credentials, redirects are errors, bodies/time are bounded, complete enumeration is required, and mutable PR/review/thread/run facts are rechecked after reading files. Current run attempts must still match the inspected attempts. A successful workflow alone does not prove a particular reported issue was reproduced or fixed.

Proof files are UTF-8 text committed at `.engineering/evidence/<sha256>.txt` on the linked head, max 16 KiB each. Every submitted artifact must match the actual file-byte SHA-256. Use synthetic/redacted material only: the repository is public. Uploads and arbitrary remote URLs remain unsupported. The saved packet digest binds the reproduction narrative, acceptance results, rollback plan, source and resulting task revision. A different human reviewer whom GitHub reports as OWNER, MEMBER or COLLABORATOR must APPROVE that exact head and include separate lines:

```
PSG_REPRODUCTION_REVIEWED <packetDigest>
PSG_ROLLBACK_REVIEWED <packetDigest>
```

These are explicit human attestations that the reviewer actually reproduced/retested the described scenario and reviewed rollback, not automatic deductions from CI. They are not a claim that the system itself executed a scenario-specific test. No self-review, unknown contributor, bot review, dismissed/old-head review or later change request can satisfy the gate. Canonical PEOS IDs are not fabricated from GitHub IDs. The founder still freshly authorizes the final decision through PEOS.

REST does not expose thread resolution. With no inline comments and complete enumeration, there are no extant review comments to resolve. With inline comments, the verifier requires a separately configured `PSG_ENGINEERING_GITHUB_READ_TOKEN` read-only GraphQL connection; complete reviewThreads, exact head/base and all isResolved values are checked twice. Missing/invalid connection, pagination, GraphQL errors, unresolved threads or changing facts block approval. No token is provisioned or new access granted by this build. Configure credentials directly in deployment settings, never chat. Existing GitHub access in ChatGPT is not silently reusable by a deployed service. Human collaborator review is required; agent-only review remains outside this gate.

The latest retained packet must match the current task/source/link. Expired, closed, cancelled or changed work is not verified. Unknown/irreversible rollback data impact remains blocked pending a separate specialist process. The final short task lock checks metadata again; before approval it also share-locks the exact unexpired evidence row. Mutable GitHub observations are bounded snapshots rather than a cross-service lock. A changed review digest or task revision requires a fresh founder confirmation.

Migration 0005 preserves the old founder_decisions CHECK (APPROVED remains disallowed there) and adds a separate append-only verified_approvals table with proof JSON and a composite FK binding evidence ID, task, reviewed revision, packet digest and head. It requires true verification, no blockers, provenance metadata, and a matching audit transition. It receives SELECT/INSERT only; no new identity, credentials, ownership or UPDATE/DELETE grants. Latest decisions and idempotency reads union both stores. The same actor/request advisory lock prevents cross-store duplicate/conflicting decisions. Exact retries return the original recorded approval without granting new execution authority. Approval advances task revision and invalidates reuse of the packet for a second new decision.

Approval proof keeps metadata only, never original packet narratives. Original seven-day packet retention remains intact. The new optional signed `verificationVersion: github.v1` marker allows the service to omit new review fields and keep approval disabled for older clients during service-first rollout. Production: verify migration/constraints in isolation and full PostgreSQL CI, apply additive schema, deploy service, then product. Restore earlier code without dropping audit tables for rollback. No synthetic approval is inserted in production.
