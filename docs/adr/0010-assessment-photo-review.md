# Private assessment photos and teacher-approved marking

SpaceCase owns assessments, rubrics, page matching, reviewed marks and approved results. PEOS owns current class and learner authority. PSG AI Platform owns live model execution. The adapter contract is `spacecase.assessment-marking.v1`; configuring an arbitrary model directly in the product is not part of this change.

Photos live in a private Vercel Blob store. Neon storage reported available but rejected bucket creation; no Neon bucket or credential was created. The Vercel store is `store_TAyHp14XhNDYkQwp`, region `fra1`, access `private`. The generated server credential is restricted to production. Previews and CI must use isolated storage or test doubles; production credentials must never be copied into a test environment. Existing authentication and product database remain in place.

The server decodes JPG/PNG/WebP, rejects animated/invalid/bomb-sized images, normalizes to bounded JPEG, removes EXIF and stores only opaque keys in Postgres. Photo reads go through an authenticated, no-store route, with current teacher assignment and current learner roster checked before returning bytes. No public or presigned URLs enter API responses. Knowing a photo, class, learner or assessment identifier grants no access.

A durable photo reservation exists before storage is written. Failed uploads remain invisible and can resume when the teacher selects the same content again. Content hashes suppress duplicates. Pending and removed reservations retain the object key for reconciliation; no untracked objects are deliberately created. Removal hides a photo and invalidates draft marking. It is not a permanent erase operation. A school retention/purge policy remains an operational prerequisite for a larger rollout. This release adds no automatic permanent deletion.

Teacher-private rubrics can be edited while DRAFT. Opening the assessment fixes the rubric. Photos are explicitly assigned to current learners and numbered 1–10. Confirmation requires contiguous pages. Any page reassignment/removal invalidates both proposals and saved review for affected submissions. Approved work cannot change until explicitly reopened with a recorded correction reason. Page and submission revisions reject stale edits.

AI runs are bounded to one learner's confirmed pages, a fixed rubric and scoped instructions. No learner name, admission number or canonical learner ID is added to the AI envelope; images may themselves contain learner information. Teacher confirmation describes that disclosure. Each execution records purpose, request ID, input hash, source revision, model and policy version. A request receipt prevents repeated execution on retry. An actor has at most 20 accepted starts per hour. Authority is rechecked immediately before disclosure and after execution; changed inputs discard the proposal. Unreadable or unsupported answers must produce uncertainty. Model output has no tool access, cannot change matching, cannot approve results, and is validated against actual questions/pages/maxima.

Reviewed marks require an explicit checked flag for every question. Approval accepts no marks from the client: it uses the saved validated review, checks the revision again and writes an immutable result. Approved results and correction events are append-only to the runtime role. Reopening clears active approval and review but preserves earlier results. Audit metadata contains references/counts/hashes and model provenance, never page bytes, rubric text or feedback.

All current action checks happen server-side. Founder, school-administrator, observer or support-agent roles alone do not confer assessment access. A teacher with a second school/class or another teacher's assessment is denied. Departed learners' matched pages and results are filtered; those records are retained without revealing them to the former class teacher.
