# ADR 0024 — Durable unverified evidence submissions

The founder may append a bounded, privacy-reviewed reproduction and rollback packet to a blocked engineering task with a current open source, unexpired brief and saved PR/head link. SpaceCase freshly resolves PEOS founder authority and source revision/status, then signs the purpose-specific request. The service obtains the task digest, source reference, PR and commits itself; none are accepted as client verification claims. Saving refers to the saved link, not a fresh GitHub inspection, and therefore does not certify that GitHub still has that head.

Migration 0004 adds an engineering-only evidence table. A task row lock serializes submission with link/cancellation/retention/decision transitions. The packet binds the resulting task revision, while submitted/recorded revisions record the explicit transition. An actor/request advisory lock and immutable canonical input hash make concurrent identical retries return one acknowledgement; a changed payload with the same UUID fails. Exact retries remain readable after cancellation or expiry without creating a new transition. The evidence row doubles as a metadata-only EVIDENCE_SUBMITTED audit event. The five latest records can be read separately; expired details are never projected even before physical removal.

Text and artifacts are synthetic/redacted, not learner/school uploads. Text is capped at 500 characters per field, ten acceptance criteria and ten artifacts per section. Hashes identify proposed proof; no arbitrary URL is fetched or files uploaded. Browser contracts contain no Node crypto dependency. A save returns UNVERIFIED regardless of reported acceptance results. Existing code-review, reproduction and rollback blockers remain in the linked summary. Approval constraints and execution gates are unchanged.

Details expire after seven days. A bounded SECURITY DEFINER function with a fixed pg_catalog search path clears only due packet JSON and records removal time, keeping immutable digests, idempotency, source/head metadata and audit history. The existing authenticated retention cron processes evidence in addition to briefs. The runtime role receives SELECT/INSERT on the new table and EXECUTE on this function, with no direct UPDATE/DELETE, ownership, schema creation or new credentials. Retention does not increment task revision: evidence is unverified and never used by current approval policy; future verified receipts must independently require unexpired packet content and current task/source/head.

The signed control envelope limit increases to 65,536 characters for bounded evidence content; service requests are stream-limited to 67,000 bytes and product acknowledgements to 131,072 bytes. All older purposes remain strict. Founder bodies retain their existing 25,000-byte limit. Audit history remains 25 events; evidence listing is latest five, no actors returned. Cancellation never erases evidence audit metadata.

The UI requires privacy confirmation and a separate save confirmation, freezes the UUID/content/revision across ambiguous acknowledgements, supports exact retry, shows unverified status and expiry, and exposes retained submission details only in the founder view. No localStorage or background polling is introduced. Leaving an interrupted submission requires checking records before creating another.

Rollout: full PostgreSQL CI and mobile synthetic UI verification, additive migration on the isolated engineering database, backward-compatible PSG service first, then product. Previous code can be restored without dropping tables or audit records. No irreversible cleanup or production synthetic task is required. Trusted live review/artifact verification remains a later integration; saving never unlocks approval.
